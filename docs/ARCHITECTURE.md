# Архитектурные решения

Один файл с нумерованными решениями, а не `docs/adr/`: для проекта одного человека
`git log -p docs/ARCHITECTURE.md` даёт историю бесплатно, а один файл ищется одним
grep'ом. Номера стабильны и не перенумеровываются — код ссылается на них
(`см. ARCHITECTURE.md A7`). Формат: контекст → решение → следствия → когда пересмотреть.

---

## A1. Типы записей — стоковые Anki, своих гибридов нет

**Контекст.** Старый генератор придумал свои типы («две карточки + ввод ответа +
озвучка» в одном) с именами вроде `BasicTypingReversedWithAudioModel`. Преподавателю
они ничего не говорят; ей знакомы типы из Anki.

**Решение.** Три стоковых типа — `Простая`, `Простая (с обратной карточкой)`,
`Простая (с вводом ответа)` — с шаблонами байт в байт из `ankitects/anki`
`rslib/src/notetype/stock.rs` (`notetypes/stock.py`, тест сравнивает). Озвучка —
ортогональная опция: к каждому типу добавлены поля `Audio Front`/`Audio Back`, ссылка
на них стоит сразу за `{{Front}}`/`{{Back}}` и при пустом поле ничего не рисует.
Стоковый CSS не воспроизводится — оформление даёт `notetypes/theme.py` (A15).

**Следствия.** Кнопки бота называются как в Anki. Имя типа внутри Anki несёт суффикс
`(anki-deck-gen)`, иначе импорт породил бы у пользователя дубль «Простая-a1b2c3».
`model_id` фиксированы и **новые** (не из старого генератора): поля изменились, а
Anki при импорте типа с тем же id и другими полями конфликтует. Правило: **изменил
поля типа — сменил id**.

**Дополнено 2026-09-04.** К трём стоковым добавлен `Простая (с вводом ответа в обе
стороны)`: стокового типа с такой парой у Anki нет, а преподавателю нужно спрашивать
слово в обе стороны и оба раза с набором. Шаблоны собраны по правилам Anki, поля те же.
Тогда же исправлен оборот карточки с вводом ответа: там должно стоять поле вопроса, а
не `{{FrontSide}}` — иначе Anki выводит разбор набранного дважды и добавляет лишнюю
черту (`typeAnsAnswerFilter` подставляет `<hr id=answer>` перед разбором сам).

**Пересмотреть,** если понадобится `Задание с пропусками` (Cloze) — другой формат
входа (одна колонка с `{{c1::…}}`).

## A2. Реестр типов — явный, в коде

**Контекст.** Пользователь хочет добавлять свои типы (вьетнамский с раскраской тонов)
и видеть их в боте без отдельной настройки.

**Решение.** `notetypes/base.py::register` — декоратор, кладущий экземпляр в `REGISTRY`;
`notetypes/__init__.py` импортирует модули с типами внизу ради побочного эффекта.
Порядок импорта = порядок кнопок. Бот показывает типы, чьи `required_columns`
укладываются в колонки Таблицы.

**Следствия.** Новый тип = один модуль + одна строка импорта. Никакого сканирования
пакета (как у clipivore для провайдеров): типов единицы, явный список читается глазами.

**Дополнено 2026-09-04.** Шаблоны и CSS лежат файлами в `notetypes/assets/`, а модули
типов только называют их. Строками в .py их не подсвечивал редактор и правились они
вслепую. Шаблонизатора здесь нет намеренно: `{{Front}}`, `{{type:Back}}`, `{{#Tags}}` —
синтаксис самого Anki, он рендерит их на устройстве, а Jinja2 истолковала бы те же
скобки по-своему. Шаблон читается дословно, файл обязан кончаться ровно одним переводом
строки (загрузчик его снимает — иначе редактор молча менял бы шаблон). Jinja2 в проекте
всё же есть, но только как dev-зависимость и только для страницы `themes/preview.html`,
которую мы генерируем сами.

## A3. Без состояния до правки строк: контекст живёт в `Pending`

**Контекст.** Между загрузкой Таблицы и постановкой Задания — несколько шагов
кнопками и, возможно, диалог правки. Что-то должно помнить разобранную Таблицу.

**Решение.** Один носитель — `bot/pending.py`: `user_id → Pending(table, deck_name,
fixes, skips, status_message_id, deadline)`, ≤ 1 на человека, TTL 30 минут, каждый
шаг диалога продлевает. Выбор Типа/Языков/Озвучки едет в `callback_data` кнопки
(`s:basic-reversed:en-ru:both` — 27 байт из 64), FSM не нужен. Клавиатуры висят на
статус-сообщении; правило «отвечать на сообщение-источник» не используется — два
способа найти контекст разошлись бы. Новый Источник от того же человека сбрасывает
и FSM, и `Pending`.

**Следствия.** Воркер в `Pending` не смотрит: `BuildRequest` самодостаточен. Перезапуск
бота теряет разобранные таблицы — человек шлёт снова, это дёшево.

## A4. FSM только для текста от человека, хранилище с потолком

**Контекст.** Правка строки и имя колоды — единственные шаги, где бот ждёт текст.
FSM-мидлварь aiogram отрабатывает раньше нашей проверки доступа, и стоковый
`MemoryStorage` создаёт запись на каждого Постороннего.

**Решение.** `bot/storage.py::BoundedMemoryStorage` — LRU на 1000 ключей; ключ без
состояния и данных не хранится. Состояния два: `FixRows.fixing`, `Rename.waiting`.
«Первая нерешённая строка» вычисляется из `Pending` каждый раз — в FSM нет ни индекса,
ни копии списка.

## A5. Один воркер, очередь на пять, работа в потоке

**Контекст.** Сборка — сотни запросов к Google TTS; общий кэш mp3 на диске; супервизор
убивает процесс без `WATCHDOG=1` дольше 90 с.

**Решение.** `runtime/worker.py` (перенос из clipivore): обработчик ставит Задание в
`RequestQueue`, единственный `RequestWorker` разбирает по одному. `build_package`
синхронна и крутится в `asyncio.to_thread`; озвучка идёт **последовательно по фразам**
(старый генератор запускал задачу на фразу — 1000 параллельных запросов). Поток нельзя
отменить, только попросить: между фразами проверяется `threading.Event abandoned`,
воркер взводит его при таймауте/отмене. `asyncio.timeout` обнимает только работу;
отправка файла и Вердикт — вне дедлайна. Мёртвый воркер = `SIGTERM` процессу.

## A6. SQLite только для доступа и настроек

**Контекст.** Инвайты и `/allow` требуют хранить список Гостей; истории Заданий не нужно.

**Решение.** Перенос `services/access.py` и `db/engine.py::create_db` из lesson-tracker
вместе — `allow_user` делает `begin_nested()`, который под pysqlite без
`isolation_level=None` сломан; `READONLY` нужен, потому что проверка доступа идёт на
каждом апдейте и не должна брать блокировку записи. Unit-of-work, outbox, dishka —
не переносятся: писем тут не теряют, писателей единицы. Плюс таблица `user_prefs` —
последние Настройки колоды («Как в прошлый раз»). Alembic на старте, до `asyncio.run`.

## A7. Заголовок строгий, регистр не важен

**Контекст.** Пользователь решил: заголовок обязателен, минимум `Q`/`A` или `Вопрос`/`Ответ`.

**Решение.** `tables/headers.py`: сопоставление после `strip()` и снятия BOM, без учёта
регистра — сознательное смягчение «строгого»: «вопрос» и «Вопрос» отличать бессмысленно.
Прочие колонки сохраняют имя — на них опираются кастомные типы. Нет `Q`/`A` → отказ,
в тексте которого стоит то, что реально было в первой строке.

## A8. Имя колоды: база, лист, колонка

**Решение.** `deck_name` + `::<лист>` (если листов больше одного) + `::<Deck>` (если
колонка есть). Одно правило вместо «или-или». `deck_id` детерминирован по имени
(sha1) — повторная сборка ложится в ту же колоду Anki.

## A9. Ссылка Google Sheets — весь документ как xlsx

**Решение.** `export?format=xlsx`, `gid` игнорируется: вкладка = подколода, значит нужны
все. Закрытая таблица иногда отвечает 200 со страницей логина — детектируем по
`Content-Type: text/html` и хосту `accounts.google.com`, не по коду.

## A10. Вставленный текст — черновик, который копится

**Решение.** Хотя бы одна строка с разделителем ` / ` (слэш с пробелами) или табуляцией,
и таких строк не меньше половины. Строка без разделителя среди строк с ним — Проблемная
строка для диалога. Имя колоды у текста спрашивается до сводки.

**Пересмотрено 2026-09-04.** Разделителем было тире (` — `/` – `/` - `), но это
типографский знак: он живёт внутри самих фраз («Москва — столица»), и такая строка
резалась посередине. Прямой слэш с обязательными пробелами внутри фраз почти не
встречается — заодно исчезла нужда требовать две строки, которая раньше защищала от
случайной фразы с тире, а на деле мешала прислать одну запись.

**Черновик (2026-09-04).** Одного сообщения мало: колода редко готова целиком к моменту,
когда о ней подумали. Первая строка открывает **черновик** — тот же `Pending`, но с
непустым `draft`; каждое следующее сообщение дописывает свои строки, Таблица и проверка
пересобираются заново, а «Готово» закрывает приём и передаёт человека в обычный поток
(имя колоды → сводка → Тип записи). Пачка строк одним сообщением работает по-прежнему:
это просто черновик, законченный сразу.

Внутри черновика годится **любой** текст, а не только похожий на таблицу: человек уже
сказал, что набирает колоду, и строка без разделителя — не повод молчать, а Проблемная
строка для диалога правки. Исключения — команды (`/…`) и любой не-текстовый Источник:
файл и ссылка не двусмысленны и заменяют черновик целиком. Клавиатура черновика
переезжает вниз с каждым сообщением (старое сообщение удаляется): иначе «Готово»
уехало бы вверх и стало недосягаемым.

## A11. Тексты — русские, простые, в одном модуле

**Решение.** Все строки в `bot/texts.py`, без `parse_mode`: ответы цитируют имена листов
и вопросы из таблиц — простой текст ничем не сломать. Тест следит за отсутствием
разметки и совпадением плейсхолдеров. Словарь — CONTEXT.md.

**Исключение** (2026-09-04): `HELP` идёт с `parse_mode=HTML` — жирные подзаголовки,
ссылка на пример словами, превью ссылки выключено. Текст статичный, единственная
подстановка (URL примера) экранируется; тест разрешает в нём только `<b>` и `<a href>`.

## A12. Деплой живёт вне репозитория

**Решение.** Как у соседних ботов: rc.d-скрипт, запись в реестре `deploy_bots` и env-файл —
в `Automation/freebsd-server` и на сервере; здесь только `docs/DEPLOY.md`. Репозиторий
публичный (сервер смотрит статус CI анонимно), поэтому в нём нет ни колод, ни данных
пользователей — только код и синтетические примеры.

## A13. CLI делит словарь с ботом

**Решение.** `anki-deck-gen --source … --note-type … --lang-pair … --audio-for …`. Тот же
`tables/` → `build/`. Проблемные строки — список с номерами и выход 1: правка в файле.
Картиночные колоды (`<img src>` + `--media-dir`) — только CLI. Старые флаги
`--anki-model`/`--templates-dirname` ушли вместе с гибридными типами.

## A14. Токен — в `TELEGRAM_BOT_TOKEN`

**Решение.** Не `BOT_TOKEN`: стоковое правило gitleaks завязано на слово «telegram»
рядом с секретом, и переименование не должно тихо открыть дыру (`.gitleaks.toml`
ловит токен ещё и по форме).

## A15. Оформление карточек — две темы, только CSS

**Контекст.** Стоковый стиль Anki (Arial 20px, чёрное на белом, серая линия) выглядит
непрезентабельно; в сообществе (anki-prettify, Ankimin) карточки давно оформляют панелью
с тенью и системным шрифтом. Преподаватель хочет выбирать вид колоды.

**Решение.** Оформление — четвёртая часть Настроек колоды (`domain.Theme`): «Карточка»
(светлая панель с тенью на сером фоне) и «Учебник» (антиква на бумажном фоне). Это
только CSS (`notetypes/theme.py`): шаблоны, поля и `model_id` не меняются. Бот спрашивает
оформление последним шагом, после озвучки; «Как в прошлый раз» помнит и его
(`user_prefs.theme`, ревизия `b7d1e2c3f4a5`, старые строки получают `card`). CLI —
`--theme card|book`. Тип со своим CSS (вьетнамский) ставит `themed = False`, и шаг
пропускается. Самая длинная callback_data — `t:basic-reversed:en-ru:both:book`, 32 байта.

**Следствия.** CSS опирается только на то, что Anki даёт на всех платформах (проверено
по исходникам десктопа, AnkiDroid и мануалу AnkiMobile): класс `card` на `body`,
`nightMode` в ночном режиме, `hr#answer`, `#typeans`, svg кнопки озвучки. Шрифты только
системные. Поле ввода Anki рисует с inline-шрифтом Arial 20px — в темах есть
`!important`. Смена CSS не требует нового `model_id`: при импорте Anki обновляет тип с
тем же id, если поля и шаблоны совпали, а mtime новее (rslib,
`update_or_duplicate_notetype`; genanki ставит mtime = время сборки) — новая тема
доезжает и до уже импортированных колод.

Как темы выглядят, видно без Anki: `themes/preview.html` собирается из самих тем и
настоящих шаблонов (`scripts/build_theme_preview.py`), тест ловит протухшую страницу.

**Пересмотреть,** если тем станет больше трёх: кнопки перестанут влезать в один экран,
понадобится превью картинкой или пресеты «для языка / для терминов».

## A16. Имена файлов — только ASCII, метки и имя колоды — нет

**Контекст.** Колода «Ппппп» уезжала в Telegram файлом `ппппп.apkg`, и AnkiDroid
отказывался её открыть: «stream did not contain valid UTF-8». Разбор архива показал,
что внутри всё корректно — имена записей в zip, JSON медиа и тексты в SQLite валидны;
кодировку теряет само имя файла, пока оно идёт через Telegram и кэш Android.

**Решение.** Имена файлов латинизируются `anyascii` (ISC, чистый python — на FreeBSD
без Rust ставится колесом, пин ports не нужен): и `.apkg`, и mp3 в кэше озвучки.
Латинизация — отдельный шаг в `build/slug.py`, а не внутри `sanitize()`: `sanitize()`
чистит ещё и **Метки**, а их человек видит в Anki, и «глаголы» должны остаться
«глаголами». Имя колоды внутри Anki тоже остаётся как его написали.

**Следствия.** Хэш в имени mp3 по-прежнему считается от исходного текста, поэтому «шар»
и «schar» не делят один файл. Формат имени кэша сменился второй раз — mp3 с
кириллическими именами, записанные до 2026-09-04, остались сиротами: у кэша нет
вытеснения, чистить его пока приходится руками.

**Пересмотреть,** если понадобится отдавать файл с человеческим именем — тогда имя
придётся передавать Telegram отдельно от имени на диске.
